# Claude Code 执行指导：The Distillation Tax

> **这是一个诊断式 benchmark 项目，不是方法项目。**
> 目标：量化"视频扩散模型被少步蒸馏加速时，到底丢了哪些生成能力、丢多少"，并把退化**因果地**归因到不同来源。
> 阅读顺序：§0 决定值不值得做，§2 是整个项目的骨架（改错了全篇作废），§5 之前不要写正式代码。
> 你有较大自主权，见 §9。

---

## §0 诚实评估：这个 idea 的成色与最大风险

### 现象本身不是新的
"少步蒸馏会损害视频生成能力"已被反复记录：

| 已有工作 | 报告的退化 |
|---|---|
| DynaForcing (arXiv 2608.17707) | Self-Forcing 的 dynamic degree 从 0.80 掉到 0.00，而画质分反而上升 |
| Adaptive Video Distillation (arXiv 2603.21864) | 无时序正则时动态度掉 >10 个百分点 |
| CoDMD (arXiv 2606.21982) | 退化幅度随模型规模**变号**（1.3B 与 14B 方向相反） |
| Data-Forcing Distillation (arXiv 2606.18478) | 多样性与保真度退化 |
| DistillAlign (arXiv 2607.26811) | 提出 teacher-normalized precision/coverage 协议 |

**每一篇都是"修复方法"论文，各自报自己的退化数字，口径互不相同、无法横向比较。** 没有人把它做成可复用的独立诊断工具——这是空位所在。

### 那这篇的贡献到底是什么
**不是"发现蒸馏有害"，而是三件事：**

1. **因果分解**：把 teacher→student 的能力差拆成四个互相独立的来源（少步采样 / 蒸馏权重 / 因果化 / CFG 差异），而现有工作全部混在一起报。**这是本项目真正的学术贡献，见 §2。**
2. **配方归因**：同一个 teacher 下比较不同蒸馏配方，回答"是 DMD 本身的问题还是某个配方的问题"。DynaForcing 已给出一个例子——CausVid 的动态度稳定在 0.43 左右不塌缩，说明塌缩源于 unanchored self-conditioning 而非 DMD 蒸馏本身。把这种归因系统化。
3. **多轴不可归约**：证明"蒸馏税"不是一个标量，不同配方在不同能力轴上的代价不同，从业者需要按需选型。

### 最大风险：税矩阵是 rank-1
**如果所有配方在所有轴上都按同一比例退化**（即 method×axis 矩阵本质上是秩 1 的），那么"多轴诊断"的框架就塌了——你实际上只测到了一个标量"退化程度"，论文退化成"已知现象的汇总表"，很薄。

**这是必须在 pilot 阶段就判定的事。** 判据写在 §5 阶段 1。

### 什么时候应该放弃
- pilot 显示税矩阵近似 rank-1（轴间相关系数普遍 >0.9）→ 框架塌，重新评估。
- pilot 显示因果分解做不出来（比如 few-step teacher 的表现与 student 几乎一致，说明退化几乎全部来自"步数少"而非蒸馏）→ 这其实是个**有意思的负结果**，但要重写叙事，来讨论。
- 发现有人已发布跨方法的蒸馏退化诊断 benchmark → 评估差异度。

### 有利条件
- 全程**纯推理**，单卡 24GB 可行，无需训练。你此前 TAS 项目的 Wan2.1 基础设施（无 T5 加载的推理路径、度量脚本）可直接复用。
- 落在 Prof. Tu 主推的视频生成评测方向（他是 CVPR 2026 VGEB workshop 的组织者之一），PI 背书天然。
- 与你已投的 ViTeX-Bench 形成评测系列。

## §1 核心主张与判据层级

**C1（必要条件）**：teacher→student 存在**可测量、超过噪声**的能力退化，且该退化在至少一个轴上**不能**被"步数变少"单独解释。
→ C1 死（退化全部来自步数，与蒸馏权重无关）→ 叙事必须重写，来讨论。

**C2（论文的核心卖点）**：method×axis 的税矩阵**不是 rank-1**——不同配方在不同轴上的代价结构不同。
→ C2 死 → 框架塌，退化为薄论文。

**C3（加分项）**：能把退化归因到具体机制成分（因果化 vs 蒸馏损失 vs CFG），给出"要保 X 能力就选 Y 配方"的可操作结论。
→ C3 死 → 少一层深度，不致命。

**实验优先级：先测 C2（最便宜且决定框架生死），再补 C1 的因果分解。**

## §2 实验的因果骨架（本项目最重要的一节）

### 2.1 teacher 与 student 的差异不只是"蒸馏"

这是整个项目最容易犯的错误。以 Wan2.1-T2V-1.3B 为例，把它和 CausVid / Self-Forcing 比，差异同时包含：

| 差异来源 | 说明 |
|---|---|
| **(a) 采样步数** | 50 步 → 3~4 步 |
| **(b) 权重被蒸馏改写** | DMD / 对抗蒸馏改了模型参数 |
| **(c) 架构被因果化** | **CausVid 和 Self-Forcing 把双向 DiT 改成了因果自回归 + KV cache。这是架构改变，不是蒸馏。** |
| **(d) CFG 用法不同** | teacher 用 CFG（典型 5.0~7.5），蒸馏学生通常把 guidance 蒸进去、推理时不用 CFG |

**如果你把 (a)(b)(c)(d) 混在一起报一个"蒸馏税"，审稿人第一个问题就是"你怎么知道这是蒸馏造成的而不是因果化造成的"，而你答不上来。**

### 2.2 用对照组把四个来源拆开

必须跑的对照组（以 Wan2.1-1.3B 家族为例）：

| 编号 | 配置 | 隔离的变量 |
|---|---|---|
| **T-full** | Wan2.1-1.3B，50 步，CFG=默认 | 实用基线（从业者放弃的东西） |
| **T-few** | Wan2.1-1.3B，**同样 3~4 步**，CFG=默认 | 隔离 (a)：只少步、不蒸馏 |
| **T-nocfg** | Wan2.1-1.3B，50 步，**CFG=1**（关闭） | 隔离 (d)：CFG 对多样性的影响 |
| **S-bi** | **FastWan2.1-T2V-1.3B**（双向 DMD 蒸馏） | (a)+(b)，**不含因果化** |
| **S-causal** | CausVid | (a)+(b)+(c) |
| **S-sf** | Self-Forcing | (a)+(b)+(c)+self-rollout |
| **S-cf** | Causal-Forcing | 同上，不同配方 |

**关键设计**：`S-bi`（FastWan，双向 DMD）的存在，让你能把 **因果化的代价 = S-causal − S-bi** 单独算出来。没有 S-bi，你根本无法区分蒸馏和因果化。**这一组不能省。**

于是税可以分解为：

```
总税  = T-full − S-causal
  ├── 步数税      = T-full − T-few
  ├── 蒸馏权重税  = T-few  − S-bi
  └── 因果化税    = S-bi   − S-causal
CFG 的影响单独用 T-full vs T-nocfg 标定
```

**这张分解表如果做出来，就是论文的 Figure 2，也是全篇最硬的贡献。**

### 2.3 CFG 是多样性轴的头号混淆

CFG 众所周知会压低多样性。teacher 带 CFG、student 不带 CFG——**多样性的差异可能主要来自 CFG，方向甚至可能反过来（student 比 teacher 更多样）**。

处理方式：对 teacher 扫一遍 CFG ∈ {1.0, 3.0, 5.0, 7.5}，把 teacher 的多样性画成 CFG 的函数，然后看 student 落在这条曲线的哪个位置。**如果 student 的多样性相当于 teacher 在 CFG=7.5 时的水平，那结论就不是"蒸馏毁了多样性"，而是"蒸馏把模型固化在了一个高 guidance 的工作点上"——这是完全不同、而且更有意思的论断。**

## §3 硬约束与陷阱

### 3.1 多样性与质量是耦合的，不能用单一标量

输出垃圾的模型多样性最高。所以"跨种子平均成对距离"这个指标单独看是有毒的。

**必须用能分离保真度与覆盖度的指标**：在视频特征空间（VideoMAE 或 V-JEPA-2 特征）上算 **precision / recall**（或 density / coverage）。precision 掉 = 质量下降；recall 掉 = 模式覆盖收窄。蒸馏的典型签名应当是 **precision 持平或上升、recall 下降**——这个签名比"多样性下降了"精确得多，也更难被攻击。

如果要保留一个直观指标，用跨种子 DreamSim 成对距离**作为辅助**，并且必须与 precision/recall 一起报。

### 3.2 动态度指标会把镜头运动和物体运动混为一谈

你在 TAS 项目里已经踩过这个坑：光流幅度类指标会被抖动和全局镜头晃动刷高。

**做法**：用 RAFT 算光流后，把运动分解为**全局分量**（拟合单应或仿射，代表镜头运动）与**残差分量**（代表物体运动）。分别报。

蒸馏可能杀掉物体运动而保留镜头 pan，也可能相反。**这个分解本身就可能是一个 finding**，而且能防住"你测的只是抖动"的质疑。

### 3.3 不要做加权聚合总分

诱惑很大：造一个 "Distillation Tax Index" 单标量排名。**不要。**

理由有二：
1. ViTeX 的审稿人已经就"13 个指标里没有 primary"提过意见，而你导师的决定是**不做跨轴加权聚合，改用 3 个 primary metric + Pareto front**。这篇如果搞一个加权总分，是在走导师已经否掉的路。
2. 加权总分会直接掩盖 C2（多轴不可归约）这个核心卖点——你辛辛苦苦证明"不同配方代价结构不同"，然后用一个加权数把它压扁了。

**正确做法**：每轴一个 primary metric，跨轴用 Pareto front 呈现，与 ViTeX 的做法保持一致。

### 3.4 种子数量决定统计功效

跨种子多样性需要足够的样本对。5 个种子只有 10 个配对，噪声极大。

**最低 8 个种子/prompt，推荐 16 个。** 所有多样性数字必须带 bootstrap 置信区间（复用你 ViTeX 的 seeded bootstrap CI 做法）。

### 3.5 生成一次，离线算所有指标

视频语料只生成一次、落盘，所有指标离线计算。不要为了算某个新指标重新生成。

存储估算：单视频 ~2MB，全量约 1.1 万条 → 约 20-25GB。可控。

### 3.6 分辨率、帧数、fps 必须严格对齐

不同 checkpoint 的默认配置不同（有的 480p/81 帧，有的 49 帧）。**必须统一到所有模型都支持的公共配置**，并在论文里写死。不对齐的话，动态度和光流指标完全不可比。

### 3.7 prompt 集要覆盖"蒸馏敏感"区

在通用 prompt 上退化可能很小。已有工作提示退化在这些场景最明显：多物体交互、快速运动、罕见组合、物体数守恒。

**做法**：VBench 标准 prompt 作为主集，另建一个"蒸馏敏感"子集（100 条左右，快速运动 / 多物体 / 罕见事件）。分别报。如果两个子集上税的大小差异显著，本身也是 finding。

## §4 五轴度量的具体定义

| 轴 | primary metric | 实现 | 防守点 |
|---|---|---|---|
| **A1 模式覆盖** | recall（特征空间） | VideoMAE / V-JEPA-2 特征上算 precision-recall | 与 precision 配对报，避免"垃圾=多样"的陷阱 |
| **A2 跨种子多样性** | 成对 DreamSim 距离（辅助 A1） | 同 prompt ≥8 种子，两两算 | 必须同时给 teacher 的 CFG 扫描曲线 |
| **A3 运动幅度** | 残差光流幅度（物体运动） | RAFT → 分解全局/残差 | 分开报镜头运动与物体运动 |
| **A4 语义/组合遵循** | VQAScore 或 VBench 语义维度 | 标准工具 | 在"蒸馏敏感"子集上单独报 |
| **A5 时序质量** | VBench temporal 维度 | 标准工具 | 注意与 A3 反向耦合（帧越静止越"平滑"） |

**注意 A3 与 A5 天然反向**：运动越少，时序一致性分越高。这正是 VBench 总分掩盖退化的机制——**把这一点明确写出来，它是本文动机的核心论据**。

## §5 分阶段实验

### 阶段 0：环境、模型、prompt 集（3-4 天）

模型（先只做 Wan2.1 家族，把因果骨架跑通）：

```bash
# teacher
hf download Wan-AI/Wan2.1-T2V-1.3B-Diffusers --local-dir ckpt/wan-teacher
# 双向蒸馏学生（关键对照，不可省）
hf download FastVideo/FastWan2.1-T2V-1.3B-Diffusers --local-dir ckpt/fastwan
# 因果学生
hf download gdhe17/Self-Forcing --local-dir ckpt/self-forcing
# CausVid / Causal-Forcing 按各自 repo 说明获取
```

产出：每个模型能生成一段视频；打印并记录所有配置（步数、CFG、分辨率、帧数、fps、scheduler）；统一公共生成配置。

**验收**：七组配置（T-full / T-few / T-nocfg / S-bi / S-causal / S-sf / S-cf）全部能跑。任何一组跑不通，先解决再往下。

### 阶段 1：rank 判定 pilot（决定框架生死）

**这是最重要的一步。**

- 30 条 prompt（15 通用 + 15 蒸馏敏感）× 8 种子 × 7 组配置
- 算全部 5 轴
- 构造 method×axis 矩阵（行=配置，列=轴，值=相对 T-full 的标准化 delta）
- **算轴间相关系数矩阵、以及该矩阵的奇异值谱**

**判读**：

| 看到什么 | 结论 |
|---|---|
| 轴间相关系数普遍 <0.7，或第二奇异值占比可观（比如 >20%） | **C2 成立，税矩阵非 rank-1，框架站得住，全力推进** |
| 所有轴高度相关（>0.9），谱近似 rank-1 | **C2 死**，多轴框架塌，停下来讨论 |
| `T-few` 的表现与 `S-*` 几乎一致 | **C1 死**——退化几乎全来自步数而非蒸馏。这是有价值的负结果，但要重写叙事，停下来讨论 |

算力：teacher 50 步在 4090 上约 4 分钟/条（官方数字，5 秒 480p 无优化）。30×8=240 条 → 约 16 小时。T-few 和学生都很快（秒级到十几秒）。CFG 扫描另加。**pilot 的墙钟时间主要是等 teacher 生成，约 1-2 天。**

### 阶段 2：因果分解（C1/C3）

在 pilot 通过后，把 §2.2 的分解表做实：算出步数税 / 蒸馏权重税 / 因果化税各占多少，带 CI。

产出：论文 Figure 2（分解堆叠图）。

### 阶段 3：全量 + 跨家族

- prompt 扩到 200 条，种子 8-16
- 家族扩到 ≥3：Wan2.1、AnimateDiff↔AnimateDiff-Lightning、HunyuanVideo↔FastHunyuan
- 加 training-free 的效率轴：特征缓存（TeaCache 类）、PTQ 量化——这两条**纯推理、成本极低**，能把"效率税"从蒸馏推广到所有加速手段，显著增加论文分量

算力：teacher 全量是瓶颈。200×8=1600 条 × 4 分钟 ≈ 107 小时 ≈ 4.5 天连续跑。可接受，但要规划好。

### 阶段 4：人类验证与呈现

- 小规模人评（运动自然度、多样性感知），验证自动指标方向正确
- Pareto front 呈现，每轴 primary metric
- 发布：生成语料、每视频指标产物、seeded bootstrap CI、CPU-only 复现脚本（照搬 ViTeX 的发布规范）

## §8 已知的坑（按踩到概率排序）

1. **把因果化当成蒸馏**（§2.1）——不加 FastWan 这个双向对照，整篇归因错误。**最致命。**
2. **CFG 没标定**（§2.3）——多样性结论可能整个反过来。
3. **用单一多样性标量**（§3.1）——被"垃圾=多样"一击击穿。
4. **动态度没分解镜头/物体运动**（§3.2）——被指"你测的是抖动"。
5. **做了加权总分**（§3.3）——掩盖核心卖点，且与导师在 ViTeX 上的决定相悖。
6. **种子太少**（§3.4）——多样性数字全是噪声。
7. **分辨率/帧数没对齐**（§3.6）——跨模型指标不可比。
8. **为了算新指标重新生成**（§3.5）——浪费几十小时。
9. **DynaForcing 的 0.80→0.00 被当成标准 delta 引用**——那是修复论文的动机性分析、含延长训练的最坏情形，引用时须表述为"塌缩轨迹"而非中立基准值。
10. **CoDMD 显示退化随规模变号**——所以任何"蒸馏税 = X"的单一断言都是错的，必须按 teacher + 配方分层报告。

### 先自己试，解决不了再问
- 某个 checkpoint 加载失败、依赖冲突 → 按各自 repo 修；实在不行换等价 checkpoint 并记录
- 某组配置跑不通（比如 teacher 强制少步会报错）→ 想办法绕（自定义 scheduler、手写采样循环），记录改动
- 显存不够 → 降分辨率/帧数，但**必须全组统一降**，且记录

### 必须停下来问
- **阶段 1 的 rank 判定结果**——无论通过与否，这决定整个项目的形态
- **C1 死亡**（`T-few` ≈ `S-*`，退化全来自步数）——这是重要的负结果，需要一起决定怎么重写叙事
- 发现疑似抢发的工作
- 发现某个对照组在原理上跑不通（比如某个学生无法在 teacher 的公共配置下生成）
- 你发现了预期之外的现象——这种一定要说

### 一条原则
**不要为了让税看起来大而挑选有利的配置或 prompt。** 所有配置、prompt 集、种子、阈值先定后跑。如果某个家族的税很小甚至为零，那就如实报告——"某些配方几乎无损"本身就是从业者需要的结论，而且让整篇文章更可信。
